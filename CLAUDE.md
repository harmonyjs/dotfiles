## Key Concepts

- **GNU Stow** manages symlinks from repo to `~` directory
- **GNU Stow requires `-t ~`** — without it, stow targets the parent directory of the repo, not `$HOME`. The canonical invocation is `stow --restow --no-folding -t ~ .`. The `scripts/lib/symlinks.sh:run_stow()` function is the source of truth for stow flags.
- **`.stow-local-ignore`** defines files excluded from symlinking
- **`--no-folding`** flag required for `.claude` directory
- **`./scripts/bootstrap`** (or `just bootstrap <git-url>`) — entrypoint for a brand-new Mac. Walks from blank macOS install to fully configured environment, with one manual gate for 1Password desktop. The gate is **conditional** (skipped when SSH already authenticates). Supports `--dry-run` (preview, change nothing) and `-y/--yes` (unattended — never block on a prompt; human/sudo-gated steps skip with a note). See [AGENTS.md](AGENTS.md) Scenario 4.
- **`./scripts/init`** (or `just init`) — idempotent setup: brew bundle, submodules, stow, tmux plugins. Safe to re-run anytime.
- **`./scripts/post-install`** (or `just post-install`) — one-shot system tweaks: TouchID for sudo via `/etc/pam.d/sudo_local` and SSH `known_hosts` for github.com. **Sudo-aware**: skips the root-only TouchID write (with a note) when sudo isn't available, e.g. under `bootstrap -y`. Does not touch the hostname.
- **`./scripts/check`** (or `just check`) validates entire setup. Its "Stow dry run" section runs `stow --restow --no-folding --simulate -v` against `~` and goes red on a conflict (stow is all-or-nothing, so one stray real file at a linked path, a `.pyc` or a stale directory copy, blocks delivery of every new file) and on any file not linked yet (a `LINK` with no matching `UNLINK`, meaning the repo gained it after the last stow). The "Symlinks" section audits a fixed list and sees neither. `init` stows on every run for the same reason, rather than skipping when the shell links already exist. `just test-stow-check` runs its tests.
- **`session-start-stow` hook** (`.claude/hooks/session-start-stow.sh`) runs that same `check_stow_dry_run` at every `SessionStart` (~60 ms), so a blocked stow surfaces in the next session instead of whenever someone runs `just check`. When red it shows Andrey the conflict or the unlinked files (`systemMessage`) and tells the agent to mention it in one line without fixing it unasked; when green it is silent, and it always exits 0. `just test-session-start-stow` runs its tests. **Known breaker of `~/.claude/settings.json`**: the Notch HUD toggle in `Claude Usage.app` (third-party usage tracker) rewrites the file with Foundation's atomic write, which replaces the stow symlink with a regular file (mode 755, sorted keys, `" : "`, `\/` escapes) and also writes a per-machine hook URL into it; keep the HUD off. Claude Code, including the desktop app's bundled copy, writes through the symlink and keeps it.
- **`scripts/lib/git.sh`** — `ssh_ready` (1Password agent holds a key **and** GitHub authenticates it; side-effect-free probe) and `ensure_ssh_remote` (converges `origin` HTTPS → SSH, but only once `ssh_ready` passes; never downgrades). `init` runs `ensure_ssh_remote` every time, so the remote **self-heals** to SSH after you unlock 1Password; `check` reports a "Git remote" section; `bootstrap`'s manual 1Password gate is skipped whenever `ssh_ready` already passes.
- **`.claude/`** is a git submodule with Claude Code configs
- **Shared global instructions:** `.claude/CLAUDE.md` is the single submodule source for both Claude Code and Codex; `.agents/INSTRUCTIONS.md` and `.codex/AGENTS.md` are relative repository aliases. `just instructions` installs only these links and their layout guide/checker via Stow; `just check-instructions` verifies them. See [.agents/instruction-layout/README.md](.agents/instruction-layout/README.md). Keep edits in the resolved Git-backed source and preserve home symlinks.
- **`commit-pr-guide` hook** (`.claude/hooks/commit-pr-guide.sh`) injects Andrey's commit / PR / review-comment writing conventions (read verbatim from `.claude/knowledge/git-writing/`: `_common.md` + one per-surface file) at authoring time: on `UserPromptSubmit` when the prompt asks to write a commit, PR or review comment (a bare mention of the word, as in a report or an aside, does not count; lowercasing goes through `perl` because BSD `tr` leaves Cyrillic capitals), and on `PreToolUse(Bash)` for `git commit` / `gh pr create|edit|merge` / review commands. The PreToolUse path also **denies** any command that publishes AI attribution: `git commit`, `gh pr|issue|release create|edit|merge|review|comment|close`, and `gh api` writes (`-f`/`-F`/`--field`/`--input`, `-X POST|PATCH|PUT`, GraphQL mutations), found anywhere in the line, so `timeout`, `$(...)`, loops and line continuations count while a read that merely searches for the text passes. It scans the command string, every body file the line names (`--body-file`, `-F`, `-F key=@file`, `--input`, `<` redirects, with the line's own `VAR=` and `cd` applied) and an amended message. The patterns live in `.claude/hooks/attribution.py`, shared with `merge-attribution-guard`, and include the review-thread signature the desktop Auto-fix event asks for; a human `Co-Authored-By` and a mere mention of the trailer both pass. A named body file that does not exist is skipped, since the line usually writes it from a heredoc already in its text, but a checker that cannot run refuses. Both hooks find `attribution.py` beside their own real path, so that file needs no restow. Guides resolve relative to the hook (not `$HOME`), so a **`stow --restow` is required after adding or renaming guide/hook files** for the runtime `~/.claude/` symlinks to pick them up. A per-session-per-domain TTL marker dedups injection while the guard always runs. `just test-commit-guide` runs its tests.
- **`stop-ask-user` hook** (`.claude/hooks/stop-ask-user.sh`) is a `Stop` hook that asks the agent to take one more look before a working turn ends: when the turn called at least one tool, the hook returns `decision: block` once with a reminder to continue unfinished work or an obvious next step, to bring an open decision to Andrey as one self-contained question, or else simply to end the turn again. It stays silent for pure conversational turns (no tool calls), when the last tool was already `AskUserQuestion`, `ExitPlanMode` or the desktop app's `mcp__ccd_turn__wrap_up` next-step box, for subagents, and while `background_tasks` are in flight. **Loop safety is stateless**: Claude Code sets `stop_hook_active` while a turn is already continuing because of a Stop hook, so exactly one block lands per user prompt; no state files to go stale. Escape hatch for non-interactive runs (`claude -p` has no `AskUserQuestion`): `CLAUDE_NO_STOP_ASK=1` or `touch ~/.claude/.no-stop-ask`. **Wire-format gotcha, verified against the 2.1.233 binary and NOT what the published Stop docs say**: a command hook blocks with a *top-level* `{"decision":"block","reason":"..."}`; for `Stop`, `hookSpecificOutput` maps only to `additionalContext`, so a decision placed there is silently ignored. `just test-stop-ask` runs its tests.
- **`delegation-guard` hook** (`.claude/hooks/delegation-guard.py`) is a `Stop` hook that sends the agent back to work when its final message hands Andrey a job the agent could do itself. It has two stages. A broad regex (second-person words, a list of Russian imperatives, English imperatives at a clause start, a code fence) passes about a third of final messages and is meant to overfire, so add a missed phrasing there, not in the prompt. Candidates go to `codex exec` with `gpt-6-luna` at low effort (`DELEGATION_GUARD_MODEL` overrides it), which returns `actor`, `delegates` and `quote`; only `actor: andrey` with `delegates: true` blocks. A call takes 4-9 s and about 25k Codex tokens, most of them Codex's own context, so watch the ChatGPT quota. It uses Codex because `claude -p` from a desktop-app session has no login of its own. Unlike `stop-ask-user` it also runs under `stop_hook_active`, because that hook's continuation can delegate too; a marker per session and prompt in the temp directory limits it to one reminder per prompt. Failures stay silent. Every `Stop` adds one line to `~/.claude/.delegation-guard.log` with its `outcome` (`not_candidate`, `cleared`, `blocked`, `error`), and the stop after a reminder adds `after_block` with `tools_after`, which shows whether the agent went back to work. `just delegation-stats` turns the log into a local HTML dashboard (`scripts/delegation-guard-stats.py`, template beside it, output `~/.claude/.delegation-guard.html`); it stays on disk because the log quotes agent messages. Lines without `session` predate full logging, so the share of stops that reach the model ignores them. It stays silent for subagents and with `DELEGATION_GUARD_OFF=1`, which it also sets for the Codex call. `just test-delegation-guard` runs its tests.
- **Claude Code and Codex run agent commands in zsh, and agents write bash.** Two layers close the gap for both. (1) `.zshenv` sets `SH_WORD_SPLIT NO_EQUALS NO_NOMATCH` when the shell runs a `-c` string (`ZSH_EXECUTION_STRING` is set), is non-interactive, and carries an agent marker: `CLAUDECODE` (Claude Code), `CODEX_SHELL` (Codex Desktop) or `CODEX_THREAD_ID` (`codex exec`). It has to be `.zshenv`: Claude Code runs every Bash call as `zsh -c -l "source <snapshot>; ..."` and `codex exec` as `/bin/zsh -lc` with no snapshot, so `.zshrc` never runs for the latter. Every agent command therefore gets the options on its next call, no new session needed: unquoted `$R` splits, `=====` stays literal and an unmatched glob passes through as bash would. Andrey's interactive zsh and zsh script files are untouched, but any `zsh -c` spawned from an agent session inherits the marker and gets the same options. (2) **`zsh-bashism-guard` hook** (`.claude/hooks/zsh-bashism-guard.py`) is a `PreToolUse(Bash)` refusal for what options cannot fix, each with its zsh rewrite in the message. Claude Code registers it in `.claude/settings.json`, Codex in `.codex/hooks.json` (stowed to `~/.codex/hooks.json`; Codex hooks take the same `tool_name: "Bash"` / `tool_input.command` payload and exit-2 refusal). Codex skips a new or changed hook until it is trusted in `codex` → `/hooks`; the trust lands as a `trusted_hash` in `.private/.codex/config.toml`, so editing that hook's command string needs a fresh trust. `codex exec --dangerously-bypass-hook-trust` runs it once for testing, and an exported `ZSH_BASHISM_OK=1` reaches the hook through the environment and disables it. Silently wrong in zsh: `$name:X` history modifiers (`git show origin/$b:src/x` runs `$b` through `:s` and drops the path; only the letters zsh 5.9 applies, `a c e h l q r s t u A P Q &` optionally prefixed by `g w f` plus `F`/`W` with a delimiter, so `$host:port`, `$PWD:/app` and `$host:22` pass), `${a[0]}` (zsh arrays start at 1), `PIPESTATUS`/`BASH_REMATCH`/`BASH_SOURCE`/`BASH_LINENO`/`FUNCNAME` (never set). Stops mid-script while later lines run on empty variables: `${!x}`, `${!a[@]}`, `${x,,}`/`${x^^}`, `read -a`, `mapfile`/`readarray`, `shopt`, `local|declare|typeset -n`. Parameter rules apply only to text zsh expands: single quotes, `$'...'`, comments, `\$` and quoted heredoc bodies are skipped, while double quotes, `$(...)`, backticks, here-strings and unquoted heredoc bodies are checked. Command rules apply only to words zsh itself runs, so the same names inside strings, comments, `bash -c '...'` or any heredoc body pass. Bypass: `ZSH_BASHISM_OK=1`. `just test-zsh-bashism` runs its tests.
- **`merge-attribution-guard` hook** (`.claude/hooks/merge-attribution-guard.py`) is a `PreToolUse(Bash)` refusal for a `gh pr merge` that would land AI attribution on the base branch. A squash without `--body` makes GitHub join every branch commit message and its trailers, and `--merge`/`--rebase` keep them verbatim, so the hook reads the PR's commits (`gh api repos/<o>/<r>/pulls/<n>/commits`) and, when any matches the shared patterns in `attribution.py` (a `Co-Authored-By` naming Claude/Anthropic/Copilot/an AI, a "Generated with Claude Code" line, the desktop Auto-fix signature), lets through only `--squash` with a non-empty literal `--body`, `--body-file`, or `-F -` fed by a literal heredoc on that same command, whose own text is clean. `-b ""` refuses: an empty body is not shown to stop GitHub appending the commits' Co-authored-by block. `--auto` always needs that explicit squash message, since the commits can change before it lands. The invocation is found anywhere in the line (after `then`/`do`/`timeout`/`xargs`, inside `$(...)`, backquotes, `bash -c` and `eval`) by its own small shell tokenizer, so quotes, `$'..'` with its `\x`/octal escapes, heredocs and `2>&1` read as zsh would. `gh pr -R owner/repo merge` counts as a merge, a computed word where `gh`, `pr` or `merge` would stand refuses, and the word after `-c` of `rg`, `grep`, `jq` and similar is data rather than a script. It fails closed: unreadable commits, a non-github.com host, more than the API's 250-commit cap, a guard fault, and a PR it would have to infer after an earlier command in the line (`cd`, `checkout`, `export`; `gh pr checks|view`, `git fetch|log`, `echo`, `sleep` and similar read-only commands do not count) all refuse, with the fix `<number> -R owner/repo` or the URL. The exception is one bare `cd <literal path>` before a numbered merge: the repo then comes from that checkout's `origin`, read from `.git/config` as text (following `gitdir:` and `commondir` for worktrees and submodules) and never by running git or gh there, since repo config can execute code; it refuses when an include, a `url` rewrite, an `upstream`/`github` remote or a `gh-resolved` mark on another remote could make gh pick differently. gh runs only in the session directory, never with the command's own variable assignments. Bypass: `MERGE_ATTRIBUTION_OK=1`. `just test-merge-attribution` runs its tests.
- **`terrateam-stale-merge-guard` hook** (`.claude/hooks/terrateam-stale-merge-guard.py`) is a `PreToolUse(Bash)` refusal for a `gh pr merge` in `mytonwallet-org/infra` whose head carries a `terrateam plan:` status while the base has commits the head lacks that touch a planned root's `watches` in `.terrateam/roots.json`. Terrateam autoapplies the plan frozen on that head, so such a merge reverts or destroys what merged since, and `prevent_destroy` cannot help because the stale branch has no block to protect. It reads the command with `merge-attribution-guard`'s parser, loaded from the same directory, so both guards resolve `cd`, `GH_REPO`, `timeout` and `bash -c` to the same PR, and a merge it cannot read is refused. A guard fault and an exhausted 110-second budget refuse too, which keeps it under its 150-second registration timeout: a hook killed at the timeout lets the command run. The coupling cuts one way: a change to `merge_calls`, `parse_args` or `resolve_pr` makes it refuse every infra merge, so run both test recipes after touching that parser. `STALE_BASE_MERGE_OK=1` counts only as a prefix of the merge itself. It sees only the shell text: a merge run from another interpreter, a gh alias or the REST API, and a push or a merge into main in the seconds between the check and gh, are left to the infra ruleset's strict up-to-date check, which admins can bypass. `just test-terrateam-stale-merge` runs its tests against the live GitHub API.
- **`gh-dashdash-guard` hook** (`.claude/hooks/gh-dashdash-guard.py`) is a `PreToolUse(Bash)` refusal for a gh flag placed after a standalone `--` in `gh search issues|prs|code|repos|commits` or `gh skill search`. Those commands join every word after `--` into the query, so `-- "$k" --jq '...'` searches for the jq text and exits 0 with `[]`, and `-- USDe --limit 3` returns unrelated hits: an empty incident dedup that reads as clean. Every other gh command rejects a word after `--` loudly, and `repo clone`, `repo fork`, `gist clone` and `codespace ssh|cp` use `--` on purpose, so they are left alone. It splits the line with `shlex` in posix mode and keeps each word's source span, which gives a quoted word (`-- "--jq"`, searched on purpose) apart from a bare flag and lets the refusal print the whole line with the flags and their values moved before `--` and redirections kept after the query. It follows `&&`, `;`, `|`, newlines and `for`/`while` bodies, skips heredoc bodies and comments, steps over `timeout`, `xargs`, `env` and assignments, and reads a `$(...)` or backquote inside double quotes and a `bash -c` script. Not seen: an unquoted backquote, a heredoc fed to a shell, gh run from another interpreter. The flag table is copied from `gh <sub> --help`, and a test compares it with the installed gh, so a new gh flag turns the suite red instead of slipping through. A parse it cannot finish passes. Claude Code registers it in `.claude/settings.json` and Codex in `.codex/hooks.json`, where it runs only once trusted in `codex` -> `/hooks`. Bypass: `GH_DASHDASH_OK=1` before `gh` or in the environment. `just test-gh-dashdash` runs its tests.
- **`.private/`** is a git submodule with identity-bearing and machine-specific configs (see Repository Structure below for current scope)
- **Memory is NOT managed by stow.** `projects` is in `.stow-local-ignore`. Claude Code auto-memory drifts the wrong way for stow — files are *born* in `~` (runtime writes), not in the repo — so `scripts/lib/memory.sh:link_memory()` owns it instead: each `~/.claude/projects/<id>/memory` is a single **directory symlink** into the `.claude` submodule, so runtime memory writes land directly in the repo working tree. `init` runs `link_memory` (self-healing), `check` audits it via `check_memory`, and a fail-safe **SessionStart hook** (`.claude/hooks/session-start-memory.sh`) makes a project repo-backed before its first memory write. `just memory` runs the linker; `just test-memory` runs its unit tests. Durability target is *capture in the working tree* — committing memory is manual / `oneiron`-owned, never automatic.
- **Memory gotchas (baked into the linker, learned the hard way):**
  - A memory dir must be **flat** (atom `*.md` + `MEMORY.md`). `link_memory_id` refuses any dir containing a real subdirectory — partially migrating around it would move the loose files yet fail to `rmdir`, leaving a half-linked drift. Move runtime/scratch subdirs out and re-run.
  - The `oneiron` skill's audit/scratch tree lives as a **sibling** of the store — `~/.claude/projects/<id>/.oneiron/`, never inside `memory/` — precisely so it stays out of the versioned repo.
  - `memory_project_id` must reproduce Claude Code's own project-id encoding exactly, or the hook links a sibling id Claude never writes to while the real dir stays unlinked drift. The rule, read from the `claude` binary: every UTF-16 code unit outside `[a-zA-Z0-9]` becomes `-` (spaces, `~`, `_` and non-ASCII included, not just `/` and `.`); an id longer than 200 is cut to 200 and suffixed `-<base36 of abs(Java-style 31-hash)>`. It is implemented in `perl` because bash cannot count UTF-16 units. Re-verify against a new Claude Code release by comparing ids with transcript `cwd`s.
  - Claude desktop **scratch workspaces** (`~/Library/Application Support/Claude/scratch-workspaces/...`) are deliberately **not** repo-backed: each session gets a fresh dir and thus a fresh id, so versioned memory there would be orphaned. `memory_id_ephemeral` is the single predicate; `link_memory_id` skips such ids and `check_memory` does not count them.
  - Any caller that sources `scripts/lib/common.sh` outside a script file (e.g. `bash -c 'source …'`, the `memory` recipe, the hook) **must pass `DOTFILES_DIR` explicitly** — `BASH_SOURCE[1]` is empty there and the auto-derivation yields the wrong parent (`~/GitHub` instead of `~/GitHub/dotfiles`), silently linking memory into a stray tree. `common.sh` now honors a pre-set `DOTFILES_DIR`.

## Repository Structure

**Public tree (this repo):**
- `.config/tmux/tmux.conf` - tmux config (prefix: `Ctrl+Space`)
- `.config/alacritty/alacritty.toml` - terminal with auto-start tmux session "main"
- `.zshenv` - environment variables and PATH (loaded always)
- `.zprofile` - login shell config (intentionally empty)
- `.zshrc` - interactive shell config (sources `.zsh_aliases` and `.zshrc.local`)
- `.zsh_aliases` - command aliases
- `Brewfile` - declarative Homebrew package manifest (CLIs, fonts, headless utilities only)
- `scripts/bootstrap`, `scripts/init`, `scripts/post-install`, `scripts/check`, `scripts/update`, `scripts/dry-run` - lifecycle scripts (sourced from `scripts/lib/*.sh`)

**`.private/` submodule (identity-bearing, machine-specific):**
- `.config/git/config`, `.config/git/allowed_signers` - git identity + SSH signing trust
- `.ssh/config`, `.ssh/*.pub` - SSH client config and public keys for this user
- `.config/1Password/ssh/agent.toml` - 1Password SSH agent config (serves keys from the `ssh` vault; versioned so a fresh machine doesn't get 1Password's empty `vault = "Personal"` default)
- `.zshrc.local`, `.zsh_history` - per-machine shell state
- `.codex/config.toml`, `.gemini/settings.json` - AI assistant per-tool configs (Codex hooks live in the public `.codex/hooks.json`; their trust hashes stay here)
- `.config/imgcluster/.env`, `.config/tg-exporter/.env`, `.config/kcat.conf` - service-specific env/configs
- `.agents/skills/` - the personal skill catalog, reached through the `~/.agents/skills` directory symlink rather than stow (see Stow exceptions below); private because the skills name clients, internal projects and this machine
- `.local/bin/{simreap,memwatch,janitor}`, `Library/LaunchAgents/dev.vavilov.*.plist`, `.local/share/clickhouse-ci-config/` - this machine's maintenance agents and the config they install

**Public-vs-private rule:** anything that contains hostnames, public keys, email addresses, identity, credentials, or paths meaningful only to Andrey's specific machines belongs in `.private/`. The public tree is for curated tool choices and universal patterns that anyone can fork.

## ZSH Configuration Rules

ZSH files have strict separation of concerns. Follow these rules when modifying shell configuration:

| What to add | Where to put it |
|-------------|-----------------|
| PATH modifications | `.zshenv` |
| Environment variables (`export VAR=value`) | `.zshenv` |
| Prompt configuration | `.zshrc` |
| Completion setup | `.zshrc` |
| Key bindings | `.zshrc` |
| Aliases and functions | `.zsh_aliases` |
| Interactive utilities (fzf, zoxide) | `.zshrc` |
| Machine-specific settings | `.zshrc.local` (not version controlled) |

**Loading order:** `.zshenv` → `.zprofile` → `.zshrc`

**Critical rules:**
- NEVER add PATH or environment variables to `.zshrc` — they won't be available in scripts/cron
- NEVER add interactive features to `.zshenv` — it runs for non-interactive shells too
- Keep `.zprofile` empty — all PATH setup is in `.zshenv` for universal availability
- Use `.zshrc.local` for machine-specific environment variables (like `NODE_EXTRA_CA_CERTS`)

## Development Principles

**No broken states** — Never commit changes that leave the setup non-functional. If something doesn't work via Homebrew, find an alternative and automate it. The only sanctioned manual gate is in `scripts/bootstrap` where the user installs 1Password desktop — and that gate is interactive, in-band, and clearly explained to the user; it is not a "go read the docs and figure it out" comment.

**User-first thinking** — Every decision is made from the perspective of someone cloning this repo on a fresh machine. They shouldn't read code comments or debug why something didn't install.

**Automation over documentation** — If an action can be automated and the policy permits it, it must be automated. The cask-vs-dmg policy (see below) is an explicit exception: desktop GUI apps are intentionally installed manually because that's the curated update path, not because automation is infeasible.

**Curated tool sourcing** — Homebrew is for CLIs, fonts, and headless system utilities. Desktop GUI apps (editors/IDEs, messengers, productivity, browsers, 1Password desktop, office suites) are installed from their official `.dmg`. When adding a new package: if it ships a GUI app you'd otherwise launch from Spotlight, do not add it as `cask "<name>"` to the Brewfile — note it in README/AGENTS or leave it implicit.

**Attention to details** — Details matter: correct installation paths, clean directory structure, no warnings. Quality is built from details.

## AI Agent Guidelines

**Before changes:**
1. Verify all three repos (dotfiles, `.claude/`, `.private/`) are on `main`, up to date with remote, and working tree clean — report status before proceeding
2. Read [AGENTS.md](AGENTS.md) for detailed scenarios
3. Run `just check` to check current state
4. Create backups before modifying configs

**After changes:**
1. Run `just check` - all checks must pass
2. Update docs if keybindings or behavior changed
3. Preserve Catppuccin Latte theme (critical requirement)

**Submodule hygiene (`.claude/`, `.private/`):**
- Before committing or pushing, ensure each submodule is on `main` and up to date with its remote (`git -C <submodule> fetch && git -C <submodule> status`)
- If a submodule is in detached HEAD — checkout `main` and pull before proceeding
- After updating submodule content, commit the new ref in the parent repo and push both

**Critical rules:**
- Maintain macOS + Homebrew compatibility
- Always use stow for symlink management
- Create backups before config modifications
- NEVER create symlinks manually, stow has to manage them
- **Stow exceptions (runtime-written trees):** stow is the source of truth for static config, which it links *from* the repo *into* `~`. Two trees run the other way — they are written at runtime and have to land in the working tree as they are written — and each is owned by a single directory symlink instead. `scripts/lib/memory.sh:link_memory` owns `~/.claude/projects/*/memory`; `scripts/lib/skills.sh:link_skills` owns `~/.agents/skills`, which points at `.private/.agents/skills` and is why `.agents` is in `.private/.stow-local-ignore`. Both run from `init` and are audited by `check` (`check_memory`, `check_skills`). `link_skills` refuses rather than overwrites when a real directory already sits at the alias path, because that means two catalogs exist. Stow would also have mangled the skill catalog outright: `.stow-local-ignore` strips every `README.md` but one, and 58 of them are reference material inside the `cloudflare` and `turnstile-spin` skills. `.agents/skills/synced` is gitignored, being Claude's own managed sync directory with its own lifecycle. These two are the only sanctioned places symlinks are not created by stow; a third needs the same justification, not just convenience.
